# 数据分析功能重构建议

## 当前问题

1. `dashboard_page.dart` 和 `call_statistics_page.dart` 存在大量功能重复
2. 拦截类型分析使用了硬编码的标签文本，不利于国际化和维护
3. SMS统计数据在某些地方使用了硬编码值

## 已完成的改进

1. 修改了 `CallStatisticsService` 中的 `_getBlockType` 方法，使用标签ID代替硬编码文本
2. 添加了 `getAllBlockTypes` 方法，用于获取所有拦截类型的标签ID列表
3. 重构了 `BlockTypeAnalysis` 组件，使其能够动态获取并显示所有拦截类型
4. 修改了 `dashboard_page.dart` 中的SMS统计部分，使用实际数据替代硬编码值

## 建议的后续改进

### 合并重复页面

建议将 `dashboard_page.dart` 和 `call_statistics_page.dart` 合并为一个统一的数据分析页面，或者提取共享逻辑到一个基础组件中：

1. 创建一个 `StatisticsBaseView` 组件，包含共享的UI和逻辑
2. 让 `DashboardPage` 和 `CallStatisticsPage` 都使用这个基础组件
3. 或者完全合并这两个页面，保留一个功能更完整的版本

### 功能对比

| 功能 | dashboard_page.dart | call_statistics_page.dart | 建议 |
|-----|-------------------|------------------------|------|
| 总览卡片 | ✓ | ✓ | 合并实现 |
| 广告位 | ✓ | ✓ | 使用统一的广告组件 |
| 统计卡片网格 | ✓ | ✓ | 合并实现 |
| 拦截趋势图表 | ✓ | ✓ | 合并实现 |
| 拦截类型分析 | ✓ | ✓ | 使用新的动态BlockTypeAnalysis |
| 导出数据按钮 | ✓ | ✓ | 合并实现 |
| 底部导航 | ✓ | ✗ | 根据使用场景决定 |

### 满足UI设计

当前实现已基本满足 `dashboard_new.html` 中的设计要求，包括：

- 总览卡片显示月度拦截总数和增长率
- 统计卡片网格显示拦截电话、过滤短信、白名单和黑名单数量
- 拦截趋势图表支持周、月、年切换
- 拦截类型分析显示各类型占比
- 导出数据按钮

### 数据获取优化

建议进一步优化数据获取逻辑：

1. 使用缓存减少重复计算
2. 考虑使用分页加载大量数据
3. 添加数据刷新机制，如下拉刷新

## 结论

通过以上改进，我们已经解决了硬编码标签文本和假数据的问题。建议进一步合并或重构重复的页面，以提高代码的可维护性和一致性。
