# AI 辅助开发与代码修改严律 (AI Development Rules)

## 1. 强制先读源码，后做决策 (Mandatory Source Code First Analysis)
* **严禁凭空盲猜**：在执行任何代码修改、重构或脚本优化前，必须先完整通读并分析相关模块的全链路源码（例如：从 `pubspec.yaml` 到 `local.properties` 再到 `android/app/build.gradle` 的版本号传递链）。
* **搞清既有架构**：必须彻底理清现有的代码逻辑与自动化流程，尊重项目既有的成型设计。

## 2. 严禁盲目套用与抄写配置 (Prohibition on Blind Copying)
* **禁止未经对比盲目复制**：严禁在未进行严密代码对比与逻辑验证的情况下，直接套用或复制其他工作流、模板或外部文件的配置。
* **注重环境与变量差异**：对于 CI/CD 配置文件（如 `.github/workflows/`），必须核对每个 Secret 变量名、编译条件与环境变量，确保 100% 兼容。

## 3. 涉及构建/CI/签名的修改必须先向用户请示 (Strict Authorization Required)
* **变动前必须请示**：涉及版本号生成逻辑、签名策略、CI 构建步骤或关键环境配置的任何修改，必须在回复中清晰详述方案细节，**先向用户过问并获得明确许可后**，方可动操作。
* **保持改动透明**：任何修改必须向用户全面透明展示变动对比（Diff）。
