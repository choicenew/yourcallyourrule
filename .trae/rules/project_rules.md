# Code Completeness Rule

## No Omissions
Never omit or abbreviate code sections with comments like "// ..." or "// rest of code"or ‘/* 完整实现 */’. Always write complete implementations.

## Full Context
Provide the entire code block needed to understand the implementation, including all necessary imports, declarations and surrounding context.

## No Placeholders
Avoid using placeholder comments or TODOs unless they're part of the actual requested implementation.

## Complete Examples
When showing examples, include all required setup code rather than just the relevant portion.

## No Hidden Logic
Don't hide complex logic behind simple function calls - show the implementation unless it exists in visible context.

## Full Error Handling
Include complete error handling rather than just the happy path unless specifically requested.

## Explicit Dependencies
Clearly show all dependencies and imports rather than assuming they're understood.

## End-to-End Code
Provide complete end-to-end code snippets that could theoretically run if placed in the proper context.

## No Partial Solutions
Don't show partial solutions that leave key components to imagination - either provide the complete solution or clearly state what's missing.

## Full Syntax
Always use complete syntax including all optional elements like type annotations, access modifiers and semicolons where applicable to the language.
